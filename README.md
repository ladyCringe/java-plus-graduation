# ExploreWithMe (EWM)

Микросервисная версия сервиса **ExploreWithMe**. 
Монолитный `main-service` был разделён на несколько микросервисов, 
которые взаимодействуют через **API Gateway** и регистрируются в **Eureka**. 
Конфигурации централизованно раздаются через **Config Server**. Проект запускается в Docker.

---

## Общая схема

Весь внешний трафик идёт только через Gateway:

**Client → API Gateway (порт 8080) → нужный микросервис**

Gateway маршрутизирует запросы по path’ам, а адреса сервисов получает из Eureka (service discovery).

---

## Сервисы и ответственность

### Бизнес-сервисы (core)
- **event-service**  
  Управление событиями и “витриной”:
    - публичный поиск событий (`/events`)
    - публичные категории (`/categories`)
    - подборки (`/compilations`)
    - приватные события пользователя (`/users/{userId}/events`)
    - админка событий/категорий/подборок (`/admin/events`, `/admin/categories`, `/admin/compilations`)
    - просмотры событий (внутренний учёт + интеграция со stats)

- **request-service**  
  Управление заявками на участие:
    - заявки пользователя (`/users/{userId}/requests`)
    - управление заявками конкретного события владельцем (`/users/{userId}/events/{eventId}/requests`)

- **user-service**  
  Управление пользователями:
    - админские операции с пользователями (`/admin/users`)

- **core-api**  
  Общий модуль с DTO/enum и контрактами для межсервисного взаимодействия (используется всеми сервисами).

### Сервис статистики (stats)
- **stats-server** — сбор hit’ов и агрегация статистики просмотров
- **stats-client / stats-dto** — библиотека клиента и общие DTO для работы со статистикой

---

## Инфраструктурные компоненты

- **gateway-server** — единая точка входа, маршрутизация запросов (порт `8080`)
- **discovery-server (Eureka)** — регистрация сервисов и обнаружение адресов
- **config-server** — централизованная раздача конфигураций
- **PostgreSQL** — СУБД (в Docker поднимаются базы/схемы под сервисы)

---

## Взаимодействие сервисов

Межсервисное общение реализовано по REST через **OpenFeign** и service-name в Eureka.

Внутренние эндпоинты (internal API) предназначены **только для сервисов** и не используются напрямую клиентами.

---

## Конфигурации

Все настройки сервисов хранятся централизованно и раздаются через `config-server`, например:

`infra/config-server/src/main/resources/config/`

Там расположены конфиги для:
- `event-service`
- `request-service`
- `user-service`
- `gateway-server`
- `discovery-server`
- `stats-server`
